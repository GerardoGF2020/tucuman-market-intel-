# Reglas del Sistema: Tucumán Market Intelligence

## Regla de Oro: Preservación de Propiedades y Persistencia Doble
1. **Nunca borrar ni sobreescribir con muestras parciales**: 
   - Una corrida de prueba o parcial (usando flags como `--max-por-fuente` o `--max-paginas`) **JAMÁS** debe eliminar, purgar o vaciar la base de propiedades existentes.
   - Las propiedades previamente descubiertas deben conservarse siempre acumulativas.
2. **Doble persistencia (Local + Remota)**:
   - Todo dato extraído debe persistir en SQLite local (`tucuman_local.db`) Y sincronizarse con Supabase cuando esté disponible.
   - Si la red externa, Wi-Fi o Supabase fallan, el sistema opera con la base local acumulada sin perder ninguna propiedad histórica.
3. **Bajas estrictas y seguras**:
   - Una propiedad solo puede marcarse como `dada_de_baja` si se corrió un scraping exhaustivo de todas las páginas de su fuente y el aviso realmente desapareció del sitio web oficial con código 404 o retirado.
4. **Enriquecimiento continuo**:
   - Cada propiedad debe conservar su desagregación de superficies (`m2_totales` de terreno vs `m2_cubiertos` construidos), sus coordenadas geográficas validadas y su historial de precios.
